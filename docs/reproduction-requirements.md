# Reproduction requirements audit

This audit preserves all 185 checklist items supplied by the maintainer, in their original
order and exact wording. IDs R001–R185 are stable within the pinned source document.
The attached prose proposes fourteen tools; it does not constitute evidence that their
underlying runtime capabilities are implemented or validated.

**Software coverage is not native acceptance.** `supported` means the described software
contract exists; `partial` states a narrower implemented subset; `unsupported` identifies
an absent mechanism; `unverified` identifies a research/acceptance claim not yet measured.
Every linked test is a verification target. Unit fixtures do not prove actual three-agent
execution, behavioral reproduction, learning improvement or frontier transfer.

The machine-readable [audit](reproduction-requirements.json) retains the source SHA-256,
full exact text, implementation paths, test paths and a per-item boundary. This audit is
not a completion percentage: items vary greatly in size and empirical requirements.

## Verified-loop follow-up

The original per-item audit below is the `4bfe55e` baseline. The subsequent
[verified-loop extension](verified-research-loop.md) adds owned SFT serving deployment,
worker/model/transcript/evaluator provenance and durable repeated four-condition comparisons.
These are software-verified additions, with real three-agent acceptance still **unverified**.
The original 185 requirement texts and IDs remain unchanged; this addendum is not a blanket upgrade
of their empirical or broader automation claims.

## Source and scope

- Source: `Mesocosm 행동 재현을 위한 Factor와 도구 요구사항.md`
- SHA-256: `32d6935a8267462915cf5fd721b0c24c4fc0fa461e6dd0eddc1181e74dd9ba0e`
- Checklist: **185 items**, no omitted or merged items.

The workbench connects factor configuration, immutable evidence and behavior definitions,
grouped datasets, a real SFT/LoRA training path, existing worker submission, bounded
snapshots/forks, evaluation comparisons and export. It preserves the current boundaries:
no dynamic agent cloning, arbitrary message substitution, exact live rewind, general
message scheduler, activation steering or automatic experiment designer.

Original tasks, real tool execution and independent verifiers remain required. No authored
incident script, prescribed agent interaction, invented reward or fake learned checkpoint
counts as implementation or acceptance of a behavioral mechanism.
