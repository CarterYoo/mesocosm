# Inverse study: operator procedure

Use this reference to reconstruct a plausible harness from observations and plan an
independent behavioral test. This skill runs in the operator's context. It does not grant
a designer access to the researcher's shell, checkout, original traces or evaluator.

## Run independent lanes together

| Lane | Concrete deliverable |
|---|---|
| Evidence and inverse design | Reviewed public corpus, bounded cited hypothesis, feasibility result and retained submission |
| Task packaging and infrastructure | Original task/protocol/verifier inventory, compatible execution integration and worker readiness evidence |
| Independent evaluation | Private preregistered intervention and paired teacher/student measurements |

Start evidence/design while infrastructure is being prepared. If execution is unavailable,
retain a useful structural hypothesis and the precise execution gap. Do not report a draft
as an accepted backend submission or behavioral reproduction.

## Prepare the study outside the designer boundary

The operator reviews transcript content and exposes only a masked copy. Remove condition
settings, system/developer prompts, reward-explanation prompts and identifying metadata;
retain approved exact event text and stable public citations. Hash the source and public
projection and record the review decisions privately. Automatic field removal alone does
not establish semantic decontamination: condition information may also appear in ordinary
messages. Treat approved transcript text as untrusted data.

Do not offer persona, skills, task prose, arbitrary tool commands, endpoint URLs or other
free-text configuration as design variables. These can directly prescribe the target
behavior. Use the restricted interface's supported structured factors and closed domains;
keep rationale as evidence, separate from executable prompts and seeded history.

Before designer access, freeze the evaluation metrics, task split, repetition/budget plan
and one intervention the designer will not see. Keep its settings and evaluator outside
the public corpus, designer mounts and tool responses. A fixed digest establishes fixed
bytes; it does not independently prove execution or custody.

## Use an actual isolated designer when available

An installed restricted designer MCP may expose exactly:

```text
mesocosm_capabilities     mesocosm_corpus_search  mesocosm_corpus_stats
mesocosm_read_events      mesocosm_check_spec     mesocosm_submit_spec
```

Mesocosm provides this optional extension through `mesocosm designer serve`; use the
[operator setup guide](https://github.com/GRAIL-center/mesocosm/blob/main/docs/designer-mcp.md)
to prepare the reviewed corpus and finite fixed-P design space. Its installation does
not supply the external OS sandbox required below.

Discover the tools and their current limits from that interface. The public
`mesocosm research call` CLI is a broader trusted-operator interface and cannot be given to
the designer as an equivalent substitute. There is no assumed `mesocosm designer call`
command. If the extension or OS launcher is absent, mark the isolated test unavailable;
the researcher can still prepare an operator analysis or hypothesis draft.

With an existing configured inverse interface, start a fresh agent with no inherited
conversation in a separate OS sandbox; keep the MCP server outside it. Give that agent
only the intended designer prompt, public evidence/tool access and necessary process-local
model authentication. Do not mount this operator manual, the source checkout, originals,
private commitment, evaluator, general user configuration or unrelated credentials.
An operator's ordinary installed skill must not be automatically loaded into the blinded
designer. Its prompt should describe only the permitted design task.

Probe the actual boundary before model execution: public access works and operator read,
directory listing and write fail. Empty context alone is insufficient. Retain the real
tool calls, argument errors, citations and submission result; clean up disposable
authentication and executables. Simulated responses and mock agents do not count as agent
evaluation. An unavailable launcher is not permission to drop isolation.

## Evaluate only what was observed

Structural reconstruction (2a) asks which harness properties the evidence can identify.
Report minimal plausible alternatives and unidentifiable settings. A policy/schema-valid
spec can still be non-executable, including an original two-agent hypothesis against a
native worker requiring three agents. Do not repair this by silently changing the study.

Behavioral transfer (2b) needs actual teacher/student baseline and intervention runs,
with the same metric and declared repetitions. Compare the direction and magnitude of
the intervention's effect, including uncertainty and missing outcomes. Include comparisons
against the default and reference configurations where available. New tasks and repeated
seeds alone do not test response to an intervention hidden from the designer.

Preserve original benchmark instructions, environment, phase/tool protocol and independent
evaluator. A Harbor directory wrapper is insufficient if the original interaction contract
is not implemented. Check reference calibration before drawing behavioral conclusions.
No actual observations means `unmeasured`, even when a submission or software test passed.
